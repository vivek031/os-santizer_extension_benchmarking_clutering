To measure false positives we needed test cases where we know the right answer. scenarios.sh runs the paper's own example programs twice: once in a safe setup, for example root working only on root's files, and once in an exploitable setup, where a normal user (uid 1001) controls a file, a folder, the input or the arguments. 33 cases over 11 passes; for system_abs we even used a fake ls that records which user really ran it. At threshold 0.5, over 44 labelled clusters: 8 real bugs flagged, 0 false alarms, 34 safe cases correctly left low, and 2 real bugs missed. That is precision 1.00 and recall 0.80. The two misses are known blind spots: in one, root reads input that the parent shell opened from the attacker's file, so the process never opens it itself; in the other, the attacker controls root's PATH, which we do not record yet. Both need more kernel context, not different weights. This is a small synthetic test, a sanity check rather than a statistical claim.
