What we implemented

1. Kernel context os-sanitizer-ebpf, -common · ~476 lines of Rust

– Every report gets a context block filled in the kernel at the event: user IDs (real, effective, file-system), the program’s owner and permissions, the parent’s user ID, the owner and permissions of the file and its folder

– New LSM hook (observe only): flags a root process that opens another user’s file

2. JSON output --json · json_out.rs

– One record per report: pass, severity, program, PID, time, kernel context, pass details (e.g. who can write the path), full stack as binary + offset

3. Clustering cluster.py

– Same group if same pass + program + top-5 stack frames + context (root? can another user swap the file? other writers?)

4. Scoring score.py

– Gives each cluster a 0–1 risk score with a written reason (criteria on slide 12)

5. Evaluation: reproduced the paper’s Tables 2, 3 and 4 on our VM

(~40 s) Here is what we built, in four steps. First, we made the kernel tell us the context at the moment of the event: who is running, who owns the program, who owns the file and its folder. That is a small change in the eBPF code, about 480 lines of Rust. Second, every report is written as one JSON record, so a script can read it. Third, we group the duplicates. Fourth, we give each group a risk score with a written reason. And to make sure our setup still behaves like the paper's, we re-ran its three benchmarks on our VM.
